# 分析报告模板

每次分析按此结构输出。所有结论必须带证据（聊天原文 + 时间），并区分【事实】【推测】【不确定】。

## A. 当前关系状态

- **当前关系阶段**：<阶段名 / 过渡中 / 不确定>（对照历史档案，说明是维持、升级还是变化）
- **判断依据**：<引用 2~3 条关键聊天原文 + 一段时间内的互动趋势>
- **可信度**：<高 / 中 / 低，说明原因；证据不足就老实说不足>
- **双方互动特点**：<简要概括，如「一方主动分享，一方回应积极」>

## B. 最近聊天分析

- **双方主动程度**：<谁更主动开启话题，用 topic_initiations / recent_windows 数据>
- **互动质量**：<回复是否深入、是否接话、是否敷衍；不拆解单句，看整体>
- **情绪变化**：<升温 / 平稳 / 降温，证据；短期波动不急着下结论>
- **值得关注的对话**：<1~3 段能代表当前状态的关键对话原文>

## C. 关键证据

每个结论引用原文，并标注：
- 【事实】可直接验证的
- 【推测】有依据但非唯一解释
- 【不确定】证据不足

**诚实原则：推测的比例不应明显超过事实，别把话说得比证据更满。**

## D. 关系趋势

- 与历史档案（`profile.json`）中上一阶段的对比变化
- 升温 / 稳定 / 停滞 / 降温
- 重要转折点（时间 + 事件 + 证据）
- 若无明显变化，明确说「当前无足够证据表明关系变化」

## E. 下一步建议

- 是否适合主动联系 / 邀约 / 给对方空间 / 解释或道歉
- 如何尊重边界、自然推进
- **我做得不合适的地方，直接指出**，不用一味安慰
- 建议必须贴合真实语境，不使用套路化操控技巧

## F. 消息回复辅助（可选，用户提供最新对话时）

- **先判断**：当前关系状态 + 聊天上下文 + 氛围（轻松/严肃/冷淡/试探）。
- **再给回复**：
  - 优先给 1 个最合适的回复（可附 1 个备选），不必每次堆 2~3 个选项。
  - 可以说「这条不用回」「晚点再回更自然」。
- **不为了推进关系而刻意制造话题**。
- 保留用户原聊天风格（参考 `data/style.json` 和档案的 `chat_style`），不过度热情、不施加压力、不写客服话术。
